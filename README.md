# Лабораторная работа 11: CI/CD и автоматизированное тестирование

В этом репозитории реализована веб-страница с формой регистрации (с адаптивным стеклянным дизайном в темных тонах), автотесты на базе **Selenium WebDriver** + **Jest** (автоматически запускаются с Microsoft Edge локально и с Google Chrome в GitHub Actions), а также настроен пайплайн CI/CD в файле `.github/workflows/ci.yml`.

---

## 🚀 Пошаговое руководство для сдачи работы

### Шаг 1. Локальный запуск и проверка автотестов
Убедитесь, что все зависимости установлены и тесты успешно проходят локально.
Откройте терминал в папке проекта и выполните:
```bash
# Установка зависимостей (уже выполнено)
npm install

# Запуск автотестов
npm test
```
Все 4 теста должны успешно завершиться (`PASS`).

---

### Шаг 2. Создание репозитория и первоначальная публикация
Инициализируйте локальный Git-репозиторий и отправьте ветки на GitHub:

1. **Инициализируйте git и сделайте первый коммит в `main`:**
   ```bash
   git init
   git branch -M main
   git add .
   git commit -m "feat: initial commit with registration portal and ui tests"
   ```

2. **Создайте репозиторий на GitHub** (например, с именем `lab11-ci-cd`).

3. **Свяжите локальный репозиторий с GitHub и отправьте ветку `main`:**
   *(Замените `ВАШ_GITHUB_НИК` на ваш логин на GitHub)*
   ```bash
   git remote add origin https://github.com/ВАШ_GITHUB_НИК/lab11-ci-cd.git
   git push -u origin main
   ```

4. **Создайте ветки `dev` и `fix` и отправьте их на GitHub:**
   ```bash
   # Создание и отправка ветки dev
   git checkout -b dev
   git push -u origin dev

   # Создание и отправка ветки fix (от ветки dev)
   git checkout -b fix
   git push -u origin fix
   ```

---

### Шаг 3. Включение GitHub Pages в репозитории
Для того чтобы автодеплой сработал успешно:
1. Перейдите в ваш репозиторий на GitHub.
2. Откройте вкладку **Settings** (Настройки) -> **Pages** (в левом меню).
3. В разделе **Build and deployment** -> **Source** выберите **GitHub Actions** (вместо *Deploy from a branch*).

---

### Шаг 4. Проверка сбоя тестов (Пункт 5 задания)
Давайте проверим, что при внесении ошибок тесты падают:
1. Перейдите в файл `app.js` и временно измените валидацию пароля (например, сделайте минимальную длину `10` символов вместо `6`).
2. Запустите `npm test` локально. Вы увидите, что тест `should successfully register with valid inputs` упадет.
3. Верните настройки обратно, чтобы тесты снова проходили успешно.

---

### Шаг 5. Выполнение сценария с ветками и Pull Request (Пункты 6-7 задания)
Выполните пошаговый сценарий разработки через ветки:

1. Переключитесь на ветку `fix` локально:
   ```bash
   git checkout fix
   ```
2. Внесите небольшое косметическое изменение в код (например, откройте `index.html` и замените текст кнопки с `<label for="username">Username</label>` на `<label for="username">User Login</label>`).
3. Сделайте коммит и отправьте ветку на GitHub:
   ```bash
   git add index.html
   git commit -m "style: rename Username label to User Login"
   git push origin fix
   ```
4. Зайдите на GitHub и создайте **Pull Request** из ветки **`fix` в ветку `dev`**.
5. На странице Pull Request запустится workflow GitHub Actions. Убедитесь, что тесты успешно прошли.
6. Сделайте **Merge Pull Request** на GitHub. Ветка `fix` сольется в `dev`.
7. Создайте второй **Pull Request** на GitHub — на этот раз из ветки **`dev` в ветку `main`**.
8. Дождитесь прохождения тестов и сделайте **Merge**. После слияния в `main` автоматически запустится деплой на GitHub Pages!
